# Design: WASM plugins scope gate (T19.1)

## Problem

v0.1 deliberately ships no in-process plugin host (D1): extensions are data and
processes (markdown, hooks, MCP). The v0.2 question is narrow: what extension
need cannot be served by MCP, and what host contract would serve it?

## The field

See `docs/design/extensions.md` §"v0.2: the WASM contract sketch": extism 1.30
(host, not dylib/`abi_stable`, not a scripting runtime), guest exports
`spec()/subject()/risk()/call()`, host imports confined through the core guards.

## cox

If the falsifier fires, a WASM tool registers as `wasm__<plugin>__<tool>`,
deferred by default, `Risk` from its `spec()`, same permission engine in front.
It gains nothing over MCP except latency and single-file distribution.

## Falsifiers

1. Three extension requests that need context-window access, in-tool-call
   execution, or cross-call state faster than a stdio round trip — and MCP
   cannot serve them.
2. Fail-open notices hide breakage (`cox ext` reporting is wrong, not the rule).

## Review

Gate only: contract sketch carried over from T7.7; implementation (extism dep,
host wiring, `wasm__` registration) is a separate task after this gate.
