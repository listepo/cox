# Design: worktrees scope gate (T19.5)

## Problem

P15 taught surfaces to show git facts; P16 taught cox about concurrent
sessions. Worktrees combine both: parallel sessions each on their own branch
and directory. The scoping question is the mapping — one session per worktree,
or one session roaming across them?

## The field

Codex and Claude Code both recommend one session per worktree (isolation by
directory; the sandbox roots already assume one cwd). No new git primitive is
needed: `git worktree` runs through the `bash` tool today (A12).

## cox

Scoped mapping: **one session ↔ one worktree** (session cwd = worktree root,
`--add-dir` for the main checkout when cross-reads are needed). `cox sessions`
already lists sessions; the implementation task adds the worktree path to the
presence record (P16), not a new session model. Creating/removing worktrees
stays a user (or `bash`-tool) action — cox never runs `git worktree add`
unasked.

## Falsifiers

1. Users want cox to spin up worktrees per task (orchestrator mode) — then
   the "never unasked" rule reopens and needs a permission shape.
2. Cross-worktree edits in one turn break the sandbox-roots assumption — then
   the one↔one mapping is wrong.

## Review

Gate only: mapping fixed; presence-record field and TUI affordances are the
implementation task.

## Resolved (P44)

The mapping shipped as gated: one session ↔ one worktree, the main
checkout a read-only second root, and no worktree created without the user
saying so.

- **T27.3** — `cox --worktree <name>` creates or reuses
  `_worktrees/<repo>-<name>` on branch `<name>` (locked with a `cox /`
  owner) and runs the session there; the worktree is the only writable
  root. `Presence.worktree` records the path, the status line shows
  `⧉ <name>`, and `/quit` offers to remove a clean worktree (the branch is
  kept).
- **T44.1** — falsifier 1 answered: `agent(isolation: "worktree")` is how
  cox spins up a worktree per task, so it got a permission shape. Worktree
  isolation is `Risk::Destructive` whatever the preset's tools are, decided
  by `cox_permission::Engine` like any other call: it asks in `default` and
  `auto`, is denied in `plan`, and runs unasked only under an explicit allow
  rule (`agent(explore)`) or `bypass`. "Never unasked" now holds for the
  model as well as the user.
- **T44.2** — one live session per worktree is warned, not locked: a
  session starting in a worktree another live session of the project holds
  (heartbeat within 600 s) prints the holder's session id and pid and
  starts anyway. Each turn's presence text names the other sessions'
  worktrees to the model.
- **T44.3** — `/agents` rows end in `⧉ <worktree dir>`, and `cox sessions`
  marks a session whose cwd is a linked worktree with `⧉`.
- **T44.4** — `cox --resume <id>` of a worktree session reopens it in that
  worktree with the same roots as `--worktree`; a worktree that is gone is
  refused with a hint (`git worktree list`,
  `cox --worktree <name> --resume <id>`), never recreated.

Falsifier 2 has not fired: a turn still edits one worktree, the one its
session runs in.
