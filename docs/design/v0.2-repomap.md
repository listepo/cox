# Design: repo map scope gate (T19.6, amended by T43.0)

## Problem

Large repos drown the model in `glob`/`grep` round trips. A repo map — a
compact structural overview (files, symbols, call edges) — answers "where is
X" in one lookup. The scoping questions: what it contains, what budget it
gets, and where it sits relative to cache breakpoints.

## The field

Aider's repo map is the reference: tree-sitter symbols, ranked by relevance,
capped at a token budget, refreshed on edit. cox already owns the pieces
(`outline` via tree-sitter in T3.2, `instruction_budget_tokens` precedent for
budgets, T8.1 compaction for staleness).

## cox

Scoped shape: a `repomap` block assembled like instruction files (byte-stable,
inside the cache prefix, §1.9), placed last inside system[2] so breakpoint 1
stays where it is. Contents = file tree + exported symbols per file
(tree-sitter `outline`), ranked by recent git changes: uncommitted files
first, then files in `git log` order, then the rest in path order (path order
alone outside git). Capped by `[context].repomap_budget_tokens`. Files denied
by `cox_permission::Engine` never appear in the map.

Refresh policy (creator's decision, `plan.md` §6 A74): the map is built once
at session start. It is rebuilt only by an explicit `/repomap refresh` (idle
only; a changed map is a deliberate, announced prefix change) or at
compaction (which already restarts the cached prefix). Never mid-turn, never
automatically, never on `edit`/`write`.

Resume: the map text is archived and recorded by `Event::RepoMapBuilt`, so a
resumed session replays the same bytes instead of rebuilding (invariant 6).

Budget: `repomap_budget_tokens` defaults to 0 (off) until the T43.6 bench
sets it.

## Falsifiers

1. The map costs more context than it saves in tool calls — `just bench`
   (T8.5 harness) with map on/off decides; budget shrinks or the gate closes.
2. Staleness misleads the model (map says a symbol exists that an edit
   removed) — then the refresh policy is wrong, not the placement.
3. A stale map after many edits in one session leads to wrong lookups — then
   the refresh trigger changes (when `/repomap refresh` or compaction runs),
   not the placement in system[2].

## Review

Gate only: contents, budget, placement and refresh policy fixed (§6 A74);
builder and bench numbers are the implementation tasks (P43).
