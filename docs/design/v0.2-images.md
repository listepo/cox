# Design: images scope gate (T19.4)

## Problem

v0.1 refuses images (`read` rejects binary with a hint, §1.11). Roadmap v0.2
lists them. The scoping question: what content-block shape carries an image
from `Submission` through each wire format, and what stays refused?

## The field

Anthropic Messages and OpenAI Chat/Responses all carry images as content
blocks (base64 source or URL, media type attached). The loop invariant at
risk is cache-stable prefix (§1.9): image bytes must sit after the last cache
breakpoint, never inside the cached prefix.

## cox

Scoped shape: `Content::Image { media_type, bytes | path }` confined by
`path::confine` when it is a path, archived via the T2.5 archive when
truncated, translated per provider in `cox-provider` (never in core, D2).
v0.1 keeps refusing with the existing hint; the refusal text names the v0.2
gate so users can find it.

## Falsifiers

1. A provider that needs images outside the message envelope (separate upload
   call) — then the `Content` shape is wrong and the gate reopens.
2. Image bytes routinely bust the context window — then images need
   downscaling/cap policy before any wire work.

## Review

Gate only: block shape and placement fixed; per-provider translation and any
cap policy are the implementation task.
