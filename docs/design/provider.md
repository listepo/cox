# Provider layer

## Which fields decide cost

For the Anthropic backend, six fields in the body cox builds (`crates/cox-provider/src/anthropic/request.rs`) account for almost all of a session's bill. **`cache_control` placement** matters most: Anthropic prices the prefix up to each breakpoint at the cache-write rate on first sight and at the read rate (a tenth of input) afterwards, so a breakpoint on the last *stable* system block — never after the volatile `system[3]` or the turn's tail — is the difference between paying full input for the whole prompt every call and paying it once; a breakpoint on a block whose bytes changed writes a new entry instead of reading the old one, which is why `SystemBlock.cache == false` blocks are skipped even when a stale index names them, and why at most four breakpoints exist (a fifth is a 400, and cox clamps to four). **`ttl`** picks which write premium is paid: `5m` at 1.25× input, `1h` at more, worth it only when turns are further apart than five minutes. **`output_config.effort`** and **`thinking`** both buy output tokens — the expensive side of the ledger — and changing either mid-session also invalidates the messages cache, so a tier's effort is fixed for the session rather than tuned per call; a thinking block replayed to a model that did not produce it is dropped server-side before pricing, so cox drops it locally instead of paying for the bytes on the wire. **`max_tokens`** is a backstop, not a knob: it never lowers what a good answer costs, it only truncates one mid-thought and buys a retry. **`fallbacks: "default"`** costs nothing until a refusal, then re-serves the request on another model at that model's rates inside the same call, which is cheaper than the client-side replay it replaces (a replay pays cold cache writes on the new model). Every one of these lands in the `usage` ledger row for the call; a cost that is not a row does not exist.
