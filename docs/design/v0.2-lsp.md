# Design: LSP diagnostics scope gate (T19.2)

## Problem

After an edit, the model needs compiler/linter truth, not a re-read of the
file. v0.1 has no diagnostic source: `edit` returns a diff, `bash` can run a
build, but nothing feeds structured diagnostics back into the turn.

## The field

Agents that do this well treat diagnostics as tool output (read-only,
confined, archived like any tool result), never as a privileged core channel:
the trust boundary stays at `permission::Engine` + `path::confine`.

## cox

Scoped entry point: a `diagnostics` tool (deferred, ReadOnly) that queries a
project LSP server (stdio, spawned per session, killed at session end) and
returns file/line/column/message ranges. Alternative rejected for now: a hook
(hooks observe events; they cannot add structured context cheaply) and core
integration (D2: core never spawns processes).

## Falsifiers

1. A language without a usable LSP server where users still demand inline
   diagnostics — the tool needs a `bash`-fallback shape.
2. Diagnostic volume drowns the context (large `cargo check` output) — then
   the tool needs the same archive/expand treatment as T2.5, not a new channel.

## Review

Gate only: entry point fixed as a deferred ReadOnly tool; server lifecycle,
protocol subset, and per-language matrix are the implementation task.
