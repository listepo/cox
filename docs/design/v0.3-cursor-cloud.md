# Design: Cursor Cloud Agents API scope gate (T49.5)

## Problem

What a **cloud agent run** buys over **P35's local `agent -p` / `agent acp`**
subprocess: a task that **survives the laptop closing** and can run for **hours**
while the local path stops when the parent session or machine ends. Target:
background tasks that would otherwise lose **many turns** of progress to sleep,
travel, or VPN drops.

## The field

**research.md §4.3.8** (checked 2026-09-26) summarizes Cursor's programmatic
surfaces. Re-checked primary sources:

- **Endpoints doc:** Cloud Agents API **v1 public beta** — create/manage agents
  that work on repositories; accepts Basic/Bearer auth; links OpenAPI spec.
  (https://cursor.com/docs/cloud-agent/api/endpoints.md, checked 2026-09-29)
- **OpenAPI 3.0.3:** `https://cursor.com/docs-static/cloud-agents-openapi.yaml`
  (checked 2026-09-29, HTTP 200, **59 344 bytes**; 59 113 bytes on 2026-09-26
  per research.md). Agent-shaped API: `POST/GET /v1/agents`, runs, SSE
  `…/runs/{runId}/stream`, cancel, `GET /v1/agents/{id}/usage`, artifacts —
  **not** a chat/completions API.
- **Auth:** API key from Cursor Dashboard; server `https://api.cursor.com`
  (OpenAPI + research.md §4.3.8).
- **ToS:** research.md §4.3.8 found **no clause naming third-party Cloud Agents
  clients** — **flag for the creator** (not affirmatively permitted either).

No official **Rust SDK** for the Cloud Agents API (research.md §4.3.8).

## cox

**Not a `Provider`:** wire shapes do not map to Anthropic/OpenAI Messages (A54,
P35). Cloud Agents belong beside **P35's local CLI plugin**, not in
`cox-provider`.

**Event mapping (if built):** a cloud run surfaces as existing background-task
events — **`Event::TaskCreated`**, **`TaskCompleted`**, **`TaskMessage`**
(T34.8) — so TUI, stream-json, ACP, and rollout stay one stream (**D2**).

**Seam:** plugin capability under **A54** (Cursor behind plugins): network grant
+ **`CURSOR_API_KEY`** (or equivalent) per P33/P35 official-path rule. Work
**leaves the machine** (Cloud Agents clone a **GitHub** repo per API docs) — the
**permission prompt must state that** through **`cox_permission::Engine`**, never
a plugin-side bypass.

**Ledger:** each run's reported usage (`GET /v1/agents/{id}/usage` or equivalent
rows) must become a **`usage` ledger row** or the feature does not ship (plan
invariant: a cost not in the ledger does not exist).

**Types:** generate from the OpenAPI spec per **A40**; vendored YAML only via
**`scripts/vendor`** (**A48**), not hand-pasted.

**Ordering:** **P35 local CLI** should land first (`docs/design/plugins.md` §10,
checked 2026-09-29); cloud API is an additive plugin capability once ToS and
ledger mapping are accepted.

## Falsifiers

1. **Usage cannot be priced** into the ledger with acceptable accuracy — reject
   cloud backend until billing fields are documented.
2. **ToS or vendor policy** resolves **against** third-party clients using the
   dashboard API key — **reject** (creator decision required).
3. Runs **require a repo host** (GitHub via Cursor's app) cox cannot assume for
   all users — limit to opt-in plugin + explicit repo grant.
