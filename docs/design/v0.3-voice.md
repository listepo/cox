# Design: voice input scope gate (T49.3)

## Problem

Two numbers decide it: **seconds from the end of speech to an editable
prompt in the composer**, and **what one minute of speech costs**. The
baseline to beat is the operating system's own dictation, which already
types into any focused terminal, including cox's composer, at zero cost to
the ledger. Target for a cox-owned path: no slower than OS dictation, every
paid minute a `usage` row, and a gain the OS path cannot give (push-to-talk
with auto-submit, code vocabulary). Neither number was measured for this
gate; the OS dictation latency and any per-minute price below are
**unverified**.

## The field

- **Claude Code `/voice`**: hold or tap `Space` to talk; audio is streamed to
  Anthropic's servers; needs a Claude.ai account and is unavailable with an
  API key; native recorder, with `arecord`/SoX as the Linux fallback
  (https://code.claude.com/docs/en/voice-dictation, checked 2026-09-28 — as
  recorded in the P49 card; not re-fetched for this doc).
- **aider `/voice`**: records with the Python `sounddevice` package and
  transcribes with OpenAI `whisper-1` through litellm (`Aider-AI/aider`
  `aider/voice.py` at `5dc9490`, checked 2026-09-28 — per the P49 card).
- `research.md` §8.1 (field survey, checked 2026-09-22) lists `/voice` for exactly these
  two; cox's column says "none — out of scope", and §0's v0.2+ list keeps
  "voice" as deferred, not rejected.
- OpenAI's per-minute price for `whisper-1` and its newer transcription
  models is not in `research.md`: **unverified** (lead: OpenAI's pricing
  page, not fetched in this pass).
- Crates and programs already in the workspace inventory: `whisper-rs`
  (whisper.cpp bindings, "Whisper ASR"), `rubato`/`symphonia` (audio
  resample/decode) and `ffmpeg` as a mise program; no audio-capture crate
  (the workspace `rust.md`, checked 2026-09-29).

## cox

**Both vendor paths are closed or costly.** Claude Code's needs a Claude.ai
login, which D3 forbids a third party to offer; aider's needs an OpenAI key
the user may not have configured. **Plain dictation is free already**:
macOS and Windows OS dictation type into the terminal, so the composer gets
text with no cox code, no audio permission and no ledger row. The gap left
is only push-to-talk inside cox with auto-submit, and model-aware
vocabulary.

Two options if the creator wants that gap closed:

1. **Provider-agnostic transcription endpoint.** An OpenAI-compatible
   `audio/transcriptions` call (OpenAI, and local servers that speak the same
   path) added to the provider layer, never to `cox-core` (D2), resolved
   through the same key lookup as every other provider, and recording a
   `usage` row per request — a cost that is not in the ledger does not exist.
   The ledger's rows are token-shaped today; audio is priced per second or
   minute, so this option first needs a ledger unit decision. Microphone
   dependency: an audio-capture crate (lead: `cpal`, not in `rust.md`,
   maintenance **unverified**) or shelling out to `arecord`/SoX/`ffmpeg`
   (`ffmpeg` is already a mise program in `rust.md`) — the external-program
   route adds no crate but must run under `cox_sandbox::sandbox::Policy`
   like any other spawned process.
2. **Local whisper.** `whisper-rs` (in `rust.md`, used by another project)
   binds whisper.cpp: a heavy C build, so under D1 it is its own crate, off
   by default, like the tree-sitter grammars in `cox-syntax`. No network and
   no ledger row, but a model file of hundreds of MB on disk (size per model
   **unverified**) and the same microphone dependency as option 1.

Guards either way: transcribed text lands in the composer as the user's own
draft, which the user reads before sending — it is not tool output, so
`cox_sanitize::sanitize` covers it only where it is echoed back as a
transcript line, as for typed text today. `cox_permission::Engine` is not
involved: dictation calls no tool. A spawned recorder runs under `Policy`.
No new guard.

## Falsifiers

1. OS dictation mangles code vocabulary (identifiers, paths, flags) badly
   enough that users ask for a cox path — then option 1 with a prompt primed
   by the repo map becomes worth its ledger work.
2. A local speech model under N MB (N set by the creator; a few tens of MB
   is the lead) with latency no worse than OS dictation appears as a
   maintained crate — then option 2 stops being a heavy build for a niche.
3. OS dictation stops reaching terminals on a major platform — then "free
   already" is false.

## Review

**Recommended verdict: reject a cox-owned dictation path for now; reopen on
falsifier 1 or 2** — pending the creator's decision. Plain dictation is
covered by the OS at zero cost; the remaining push-to-talk gap does not pay
for a microphone dependency, a new ledger unit and either a paid endpoint or
a heavy C build. If the creator approves this, the §0 v0.2+ "voice" entry
moves to rejected-with-reopen-conditions in the same amendment; if the
creator prefers **defer**, the entry stays as it is. A **build** verdict
would need, as its §6 amendment draft: the ledger unit for audio first, then
option 1 behind the provider layer, then the TUI push-to-talk key.

**Creator's verdict (2026-09-29, `plan.md` A123): build option 2** — local `whisper-rs` in its own crate `cox-voice`, push-to-talk with auto-submit in the TUI; cards T54.1–T54.7. The §0 "voice" entry stays and points at P54.
