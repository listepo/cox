# Design: voice input scope gate (T49.3)

## Problem

Targets for any built-in dictation: **under ~2 s** from end of utterance to
editable prompt text, and a **documented cost per minute** of audio (ledger
row or explicit "free tier") so usage is not invisible.

## The field

**Claude Code `/voice`:** hold or tap **`Space`** (configurable); audio is
**streamed to Anthropic's servers** for transcription (not processed locally).
Requires a **Claude.ai account**; **not available** when Claude Code uses an
Anthropic API key, Bedrock, Vertex, or Foundry. Linux falls back to **`arecord`**
or **`rec` (SoX)** if the native recorder fails. Transcription does not consume
Claude message limits per the docs.
(https://code.claude.com/docs/en/voice-dictation.md, checked 2026-09-29)

**aider `/voice`:** records with **`sounddevice`** (Python), transcribes via
**`litellm.transcription(model="whisper-1", …)`** on the configured OpenAI-compatible
path (`Aider-AI/aider` `aider/voice.py` at commit `5dc9490`, checked
2026-09-29).

## cox

**D3** (plan.md §0, checked 2026-09-29) forbids building on Claude.ai
subscription login or undocumented ChatGPT login; both field implementations
above assume accounts or keys cox may not have as the primary auth path.

**Free today:** **macOS and Windows OS dictation** types into any terminal
(including cox's prompt) with no cox code — plain dictation is already available
(`research.md` §8.1, checked 2026-09-29).

**Remaining gap:** **push-to-talk with auto-submit** (tap-to-send) and
coding-vocabulary hints tied to the repo, without leaving the TUI keymap.

**Options if cox built dictation:**

| Option | Transcription | Microphone capture |
| --- | --- | --- |
| Provider endpoint | OpenAI-compatible `POST /audio/transcriptions` (cloud or local server) behind `cox-provider`; **`usage` ledger row** required | Platform APIs or **`cpal`** in a new leaf crate (D1: heavy deps isolated) |
| Local whisper | On-device model in a dedicated crate (C build, large binary) | Same as above |

Neither option ships in this gate; both add dependencies and maintenance surface
for a problem largely solved by OS dictation plus manual Enter.

## Falsifiers

1. OS dictation **mangles code vocabulary** badly enough that users routinely
   ask for in-app dictation — reopen with the provider-endpoint option first.
2. A **local model under ~100 MB** with acceptable latency on laptop CPUs
   appears — re-evaluate the local-whisper crate path.
3. Headless **`cox run -p`** users need voice without a TUI — a separate,
   narrower requirement than terminal dictation.

## Review

**Verdict: defer.** Rely on OS dictation for text entry; do not add audio
capture or transcription dependencies until falsifier 1 or 2 fires or the
creator elevates push-to-talk auto-submit.

Out of scope: `/voice` command, `cpal`, whisper, provider transcription wiring.
