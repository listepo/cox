# Design: architect/editor mode scope gate (T19.7)

## Problem

One loop serves both "think hard, touch nothing" and "edit fast". Today the
difference is manual (`--permission-mode plan`, `/model` overrides). The
roadmap asks for named modes. The scoping question: what exactly changes
between modes — tiers, tools, approvals?

## The field

Cursor/Copilot agent modes and Codex `plan` vs `exec` agree on the shape: a
mode is a preset over (tiers, allowed tools, approval policy), not a second
loop. The D2 core stays one state machine; the mode only changes what the
router picks and what the permission engine asks about.

## cox

Scoped mode table:

| | architect | editor (default) |
| --- | --- | --- |
| main tier | think (gated, confirmed) | code |
| write tools | denied (plan text only) | allowed per policy |
| `bash` | read-only commands only | per classifier |
| approvals | every Exec asks | per policy |

Surfaces: `/mode architect|editor` + `--mode` flag, both mapped to config
keys (invariant 12, T0.3). Subagent presets (T9.3) already narrow tools per
child; modes are the same mechanism applied to the top session.

## Falsifiers

1. Users constantly override within a mode (architect who needs one edit) —
   then modes are too rigid and should be one-shot flags, not session state.
2. A mode needs a third loop behaviour (e.g. architect running background
   research agents) — then it is a preset + `agent`-tool policy, still not a
   second loop.

## Review

Gate only: mode table fixed; flag/command wiring and preset plumbing are the
implementation task.

## Resolved (P42)

Implemented by P42 (plan.md §6 A73). A mode is a preset over the
**permission mode** and the **main tier** only:

| | architect | editor (default) |
| --- | --- | --- |
| permission mode | `narrower(configured, plan)` | `permissions.mode` as configured |
| main tier | think (confirmed, invariant 9) | the configured tier |
| write tools | denied by `plan` through `cox_permission::Engine` | per policy |
| `bash` | classifier-safe read-only commands only (`Risk::ReadOnly`) | per classifier |
| approvals | none asked: `plan` denies every non-read-only call | per policy |

- Tool schemas are never filtered by mode. system[0..2] stay byte-stable
  across a switch (invariant 1); `plan`'s deny does the narrowing.
- A mode only narrows: `cox_permission::narrower` picks the narrower of the
  configured mode and the preset's, in the order `plan < default < auto <
  bypass`, so no mode widens what `permissions.mode` allows.
- The gate's "every Exec asks" row above is superseded by `plan`'s deny
  (pending open question 1).
- Surfaces: `core.mode` / `--mode` (T42.2), `/mode` in core (T42.3) and the
  TUI (T42.4); `Event::ModeChanged` carries the mode and the permission mode
  it left in force. Headless think consent is the explicit `--mode architect`
  flag only (T42.5).
